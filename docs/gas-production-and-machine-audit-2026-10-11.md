# Water separation and machine coverage

## Water Separator

Find **Water Separator** under Storage & Transport, or use `/give @s zerog_tweaks:water_separator` for testing. It uses existing approved Crystal Growth industrial textures for now; dedicated separator artwork is still pending. Exact survival crafting costs remain deferred, so this is a functional production machine available through creative/admin placement, not a finished survival crafting progression.

Default processing:

|Input|Outputs|Power|Time|
|---|---|---|---|
|10 mB vanilla water|20 mB hydrogen + 10 mB oxygen|2,000 FE|100 ticks|

The three tanks each hold 16,000 mB and the energy buffer holds 200,000 FE. No inputs are consumed until a complete cycle commits. Either full output, missing water or insufficient FE pauses production safely. Existing unfinished progress is retained while blocked; changes to cards or configured operation values restart uncommitted progress. Pressure is **fill percentage**, not a physical-pressure unit: no leaks, explosions, damage, breathing benefits or new gas fuel behavior.

`zerog-gas-production-server.toml` configures water per cycle (1–8,000 mB), cycle FE (1–200,000) and duration (1–12,000 ticks). Outputs always remain twice/once the water volume as H2/O2. These are gameplay balance volumes, not a real chemical-volume simulation.

### Connect and operate

1. Place a separator. Feed FE through any enabled power face using an existing conduit/generator.
2. Default **Up** is water input. Use a water bucket on the top or a water pipe feeding that face.
3. Default **East** extracts hydrogen; **West** extracts oxygen. Connect separate gas-tube networks and tanks. Do not join different gases.
4. Empty gas canisters can collect outputs by clicking their assigned output faces. Filled gas canisters are not input fuels.
5. Open the panel with an empty hand. The Recipe button shows configured quantities plus base and card-adjusted FE/time.
6. Face buttons cycle Off/Water/H2/O2. Power faces have independent Input/Off controls. Cached handlers follow changed permissions; removed machines cannot keep transferring.
7. Left card socket accepts Acceleration, right Energy Coil. Tier1–6 use existing maximum2.5x speed and30% total-operation FE savings. Compact and Void are rejected because this machine has no processing item inventory.

Only installed cards drop when breaking; this block does not create a new portable tank/energy-storage item. Stored contents follow the existing stationary-machine break convention. Mining uses an iron-or-better pickaxe.

## Number2: current machine coverage, not duplicated machinery

The source audit found exact recipe adapters already delivered for the current eleven live addon profiles: nine legacy/frame machine IDs plus Geno Station and Genetic Splicer. Native processors, generators and alveary panels also already have their own purpose-specific recipe views. The new separator adds its own synchronized recipe/upgrade values and fluid/FE controls.

|Machine family|Supported controls|Upgrade contract|
|---|---|---|
|Refinery/Alloy Forge/Crystal Growth/Salvage|Item roles and FE Input/Off|Acceleration, Coil, Compact, Void|
|Geno/Splicer|Items, FE where supported, actual fluid tanks|Acceleration and Coil only|
|Centrifuge/Starmetal Smelter|Items and FE Input/Off|Acceleration and Coil only|
|Stardust/Weaver/frame assemblers/infusion aliases|Filtered item faces; no invented fluid/FE tanks|No processing cards under current rules|

|Water Separator|Water/H2/O2 roles plus FE Input/Off|Acceleration and Coil only|

Read-only recipe browsing does not grant items or start jobs. Unsupported cards, fluids and fictional processing routes are not added merely to make every machine's interface identical.
