# Mobs: sheets, data and diagrams (for agents)

This folder has everything about the 28 ZeroG Tweaks mobs:
- the PNG reference sheets (`01_regolith_crawler.png` … `28_sand_skitter.png`);
- machine-readable data (`data/`);
- diagrams (`diagrams/`).

When you implement a mob, read its row in `data/mobs.json` first. It links to every other file you need.

Everything in `data/` and `diagrams/` is generated by `docs/zero-g-tweaks-bundle/generators/mob_docs.py`, using:
- `mobs_data.py` and `mobs_food.py`: the design text, the same source as the sheets;
- `mob_specs.py`: implementation specs such as Java base class, AI goals, states and transitions;
- the repo itself: loot tables, GeckoLib files, textures, spawn-egg colours, pending spawn modifiers and recipes.

Edit those sources and re-run the generator; don't hand-edit the outputs.

## How to turn a row into Java (NeoForge 1.21.1 + GeckoLib 4.x)

1. **EntityType:** register `EntityType.Builder.of(Ctor::new, MobCategory.<mob_category>).sized(hitbox_width, hitbox_height)`.
   - Add `.fireImmune()` when `immunities` contains `fire`.
   - `hitbox_length` is for the model only. Vanilla hitboxes are square.
2. **Class:** extend `java_base`. Where it names a vanilla pattern (Rabbit, Strider, Guardian and so on), copy that class's movement control and navigation.
3. **Attributes:** `createAttributes()` from `mob_attributes.csv`. Register the attributes in `EntityAttributeCreationEvent`.
4. **Goals:** `registerGoals()` from `mob_ai_goals.csv` in priority order.
5. **States:** hold the states from `mob_state_transitions.csv` in synced entity data. The animation controller picks the GeckoLib animation for the current state.
6. **Mechanics:** implement the `mechanics` list in `mobs.json`, for example shear timers, latch/ride, burrowing and core-open windows.
7. **Wire the finished pieces:**
   - renderer: `docs/.../java/client/ZGGeoEntities.java`;
   - spawn egg: `docs/.../java/item/ZGSpawnEggs.java` (colours are in `spawn_egg`);
   - `SpawnPlacements` for natural spawners;
   - move the mob's spawn file from `pending-data/` into `src/`.
8. **Bosses:** a `ServerBossEvent` with `boss.bar_color`. Phase thresholds are in the transitions.

## Design items that have no registry id yet

The design text mentions these drops, but no item exists. Either add the item (a new id) or implement the behavior in Java:

| Mob | Design drop | Status |
| --- | --- | --- |
| Frost Warden | Frost Warden Helm (trophy) | No item. Add `frost_warden_helm`, or drop it from the design. |
| Eidolon Captain | Captain's Lantern *if spared* | Item exists (`captains_lantern`). Drop it from Java on the parley path; it is not in the loot table because it depends on how the fight ended. |
| Crater Drifter | Meteorite Fragment "as it drifts" | Block item exists. Drop it on a timer from the drift goal; it is not a death drop. |
| Ash Strider | ash 1–3 | No item. `ashfall` is a block; decide whether it drops that. |
| Dying Star | T6 crown | Not an item; it's the gate's cosmetic crown, set by the ending choice. |
| Rust Beetle | Ferrox saddle (tame) | No item. Add `ferrox_saddle`. |
| Glimmerfish | bucket of Glimmerfish | No item. Add `glimmerfish_bucket`. |
| Rift Tyrant | arena crumble | Needs a new block tag `zerog_tweaks:rift_arena`. |

Shattered Skies mobs (Meteor Maw, Mossback, Slagjaw, Shardmother, Hollow Sentinel, Tidewraith, Amethyst Stalker, Stormbitten Wyvern) are not in this folder. They live in the shared mob library under its own namespace.
